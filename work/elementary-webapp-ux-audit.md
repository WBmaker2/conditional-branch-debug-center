# 초등 학습자 UX 감사 장부

> 모드: `full` · 감사일: 2026-08-31 · 대상: 초등 5~6학년, 실과·정보
>
> 이 문서는 실제 학생 연구 결과가 아니라, 브라우저에서 관찰한 앱 상태와 오케스트레이터의 simulated learner panel 휴리스틱을 분리해 기록한다. VoiceOver 검증은 범위에서 제외한다.

## 심각도 장부

### EDU-UX-001 · P1 · 진단 화면의 근거가 전환과 함께 사라짐

- **Path/state:** 예측→추적 완료→진단, 특히 오답 진단
- **Evidence:** `DiagnosePanel.tsx`의 “위 추적판” 안내; 수동 first-mission 경로; `baseline-predict-1280.png` 이후 진단 상태 관찰
- **Observed result:** 추적판의 규칙별 결과가 진단판에 없어서 학생이 표시 개수를 기억하거나 뒤로 가야 한다.
- **Learner impact:** 진단의 핵심 근거 세기가 끊기고, 오답 뒤 스스로 회복하기 어렵다.
- **Root cause hypothesis:** 화면 전환 시 사례·규칙 결과를 재표현하는 요약이 없다.
- **Proposed change:** 진단판에 현재 사례의 규칙별 `맞음/안 맞음` 근거 요약을 다시 표시하고, 오답 피드백도 같은 근거를 가리키게 한다.
- **Verification:** 같은 first-mission 오답 순서로 진단판과 warning 상태에서 근거가 실제 표시되고, 정답을 직접 표시하지 않은 채 선택→회복이 가능해야 한다.
- **Status:** fixed · 브라우저·단위·E2E 확인

### EDU-UX-002 · P1 · 긴 수리 선택지가 맥락과 CTA를 밀어냄

- **Path/state:** 진단 정답→수리→조건 수정
- **Evidence:** 1280 브라우저에서 조건/연산자 선택 시 선택 위치로 자동 스크롤; 375 수리 화면의 긴 세로 목록 관찰
- **Observed result:** 연산자·기준값을 전부 라디오 행으로 펼쳐 수리판이 길어지고, 선택 후 제목과 사례 맥락이 화면 밖으로 올라간다.
- **Learner impact:** 무엇을 고치는 중인지 잊고, 모바일에서 핵심 CTA를 찾기 위해 과도하게 스크롤한다.
- **Root cause hypothesis:** 상호 배타적인 값 후보를 모두 같은 높이의 카드로 렌더링한다.
- **Proposed change:** 조건 선택은 유지하되 연산자와 기준값 후보를 2열 압축 라디오 그리드로 배치하고, 현재 수리 요약과 CTA를 가까이 둔다.
- **Verification:** 기존 마우스·키보드 경로와 모든 승인 수리가 통과하고, 320/375에서 제목·선택 컨트롤·재시험 버튼이 가려지지 않아야 한다.
- **Status:** fixed · 320/375 브라우저·E2E 확인

### EDU-UX-003 · P2 · 입구의 첫 행동 위계와 모바일 진행 단계가 약함

- **Path/state:** 입구 320/375/1280
- **Evidence:** `baseline-intro-320.png`; 320에서 진행 단계가 5+2행, 히어로와 미션 목록이 CTA보다 앞섬
- **Learner impact:** 첫 행동을 찾는 시간이 길고, 현재 학습 위치를 단계 라벨로 파악하기 어렵다.
- **Proposed change:** 입구에 `이번에 할 일` 요약을 추가하고 CTA를 첫 행동 패널로 묶으며, 좁은 화면 진행 단계는 한 줄 숫자 단계로 안정화한다.
- **Status:** fixed · 320 브라우저와 모바일 E2E 확인

### EDU-UX-004 · P2 · 상태 용어가 게임식·내부식으로 읽힘

- **Path/state:** 추적·진단·재시험·기록
- **Evidence:** `TracePanel.tsx`, `DiagnosePanel.tsx`, `RetestPanel.tsx`, `missions.ts`의 `당첨` 표현
- **Learner impact:** 조건 충족을 “상금/승자”처럼 오해할 수 있고, 같은 상태를 화면마다 다르게 부른다.
- **Proposed change:** 학습 의도에 맞게 `맞음`, `안 맞음`, `맞는 규칙`으로 통일하고, gap/overlap 핵심 용어는 그대로 유지한다.
- **Status:** fixed · 문구 검색·단위·E2E 확인

### EDU-UX-005 · P2 · 완료 결과의 다음 학습 행동이 약함

- **Path/state:** 기록판
- **Evidence:** 기존 기록판은 결과·인쇄·다시 시작을 제공하지만 학습 전이 행동은 직접 안내하지 않음
- **Learner impact:** 완료 후 결과를 읽고 무엇을 설명하거나 적용할지 바로 연결되지 않는다.
- **Proposed change:** 점수·순위 없이 `입력→조건→행동`을 친구에게 설명해 보는 짧은 다음 행동을 추가한다.
- **Status:** fixed · 기록 화면 단위·전체 E2E 확인

### EDU-UX-006 · P3 · 선택 상태의 접근성 이름에 장식 텍스트가 섞임

- **Path/state:** 모든 라디오 선택
- **Evidence:** `.choice:has(input:checked)::after { content: '✓ 선택됨' }`; 브라우저 접근성 스냅샷에서 선택 라벨 뒤에 선택 상태 텍스트가 합쳐짐
- **Learner impact:** 네이티브 radio의 checked 상태와 시각 장식 텍스트가 중복되고, 긴 라벨의 scan 부담이 생긴다.
- **Proposed change:** CSS 장식 체크 모양만 남기고 radio의 네이티브 checked 의미를 사용한다.
- **Status:** fixed · 접근성 검사·브라우저 snapshot 확인

## 유지·비변경 판정

- `src/domain/branchEvaluator.ts`, `src/app/sessionReducer.ts`, 고정 6개 미션과 승인 수리 계약은 변경하지 않는다.
- 현재 히어로 SVG는 규칙 레일과 가상 모형의 맥락을 보여 주는 검증된 프로젝트 자체 도식이다. 정답·수치·판정은 SVG에 의존하지 않으므로 교체하지 않는다.
- 별도 인터랙티브 시뮬레이션 엔진, Canvas/WebGL, 음성 기능, 네트워크·저장소는 추가하지 않는다.
